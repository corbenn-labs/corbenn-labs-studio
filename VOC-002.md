## 1. Problem

VOC-001 demonstrated that the Core can orchestrate G2–G6, but **does not guarantee that documented state reflects operator actions executed outside the workflow**.

During BUG-004, the visualizer was already published while `PROJECT_STATE.md`, G2, G3, and G6 continued operating under the false premise that the long-form anchor was pending. This produced potentially invalid downstream deliverables and required a costly extraordinary reconciliation chain.

VOC-002 must test whether a **minimal, reproducible protocol** can synchronize authoritative state **before** opening gates that consume that state — and only afterward validate whether G9 can open in a bounded way using operator-supplied manual analytics.

---

## 2. Hypothesis

If the operator reports an external action with minimal evidence and the CEO executes a fixed synchronization sequence (factual verification → authorized update of authoritative sources → consistency check → gate decision), then:

1. Authoritative sources will align before any downstream gate opens.
2. A full multi-specialist reconciliation will not be required to correct a single state variable.
3. G9 can open in bounded form using operator-supplied manual analytics, producing a factual baseline without strategy or causal inference.

---

## 6. Mandatory Observations

These boundaries must be preserved in execution and closure evaluation:

1. During Phase A, the **Researcher verifies the fact and proposes affected fields** — the Researcher does not apply modifications.
2. The **CEO authorizes modifications and controls the gate**.
3. The **operator physically executes** authorized modifications to files.
4. VOC-002 validates **manual controlled synchronization of one factual variable**.
5. A successful result **does not demonstrate automatic detection** of external state changes.
6. A successful result **does not demonstrate automatic prevention** of BUG-004.
7. Publication date/time is a **deliberately small and controlled test** — success does not generalize to all drift scenarios.

## 8. Success Metrics

| Metric | Success threshold |
|---|---|
| Formal delegations | ≤ 2 (Phase A: 1 Researcher; Phase B: 1 Researcher G9) |
| Corrective operator interventions | ≤ 1 (deviation correction, not full cycle recovery) |
| Documents modified in Phase A | Exactly 2: `publication-log.md`, `PROJECT_STATE.md` |
| Post-sync consistency | Synchronized field matches across both sources; associated blocker updated or removed |
| Extraordinary reconciliations | 0 (no G2/G3/G6 reconciliation cascade) |
| Time to complete sync | Measurable in one session without chat restart |
| G9 deliverable | Exists; separates facts / observations / gaps / limits |
| G9 boundaries respected | No strategy, no causality, no definitive KPIs, no cadence escalation |
| G9 opening | Only after Phase A formal pass |

## 9. Failure Criteria

- CEO delegates G9 or any downstream gate **before** Phase A completes
- Researcher produces strategy, content, or out-of-scope analytics
- Multi-document reconciliation required (BUG-004 / VOC-001 pattern)
- `PROJECT_STATE.md` and `publication-log.md` remain inconsistent after Phase A
- G9 produces strategic recommendations, platform ranking, or causal inference
- Documents outside authorized scope are modified
- Unauthorized artifacts created (e.g., bugs, new experiments) without CEO delegation
- Operator must manually reconstruct more than one correction cycle to achieve sync
- Phase A cannot complete due to missing minimum operator evidence

## 12. What Success Does and Does Not Prove

### Success proves

- A minimal manual protocol can synchronize one factual variable across authoritative sources before downstream gates consume state
- CEO can enforce gate order between state sync and G9 opening
- G9 baseline can produce bounded factual output from operator-supplied manual analytics

### Success does not prove

- Automatic detection of external platform or production changes
- Automatic prevention of BUG-004 or documentation drift
- Generalization to multi-variable or multi-document drift scenarios
- Validation of Office Manager, Analytics Specialist, or Publishing gates
- Low-supervision operation without operator physical file execution
