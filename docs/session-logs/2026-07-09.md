# Executive Summary

El 2026-07-09 Corbenn Labs completó la transición de arquitectura documental a **primera capa ejecutable operativa**: Manager Python como orquestador LLM, workflows n8n para Research-v1 y Marketing-Strategist-v1, y un flujo padre `Manager Main` que encadena investigación y estrategia con contexto autoritativo inyectado.

Se validó Research-v1 con GPT-5.5 y Web Search integrado, se creó Marketing-Strategist-v1 como consumidor de investigación aprobada, se reestructuró Manager Main con Form Trigger y mapeo dinámico de campos, y se archivó formalmente Research-v1 v1.0 bajo la estructura aprobada `docs/specialists/` + `workflows/`. El commit `f1557aa` consolidó Manager, infraestructura n8n y estado operativo en el repositorio, con push a `origin/main`.

Este día representa un hito porque Corbenn Labs pasó de contratos y diseño a **ejecución real encadenada** (formulario → contexto → research → estrategia), con separación explícita de responsabilidades entre especialistas y sin duplicar `MasterContext_v2.md` como autoridad arquitectónica.

# Problems Encountered

1. **Campos vacíos o incorrectos en Research-v1** — El nodo `Call 'Research-v1'` en Manager Main inicialmente no propagaba correctamente `mission`, `query`, `project`, `source` y `authoritative_context`; en inspecciones intermedias los valores eran fijos o el mapeo `workflowInputs.value` quedó vacío `{}`.

2. **JSON vacío / inputs faltantes en workflow hijo** — Research-v1 recibía ejecuciones sin contexto completo cuando el flujo padre no mapeaba expresiones ni cargaba `authoritative_context`.

3. **Mapeo dinámico incompleto** — Desalineación entre salida del Manager (`input.query`, `context.project`) y campos planos esperados por Research-v1.

4. **Configuración con nodos Merge** — Iteraciones tempranas del flujo padre complicaron la unión de ramas; la arquitectura final eliminó Merge y usa secuencia lineal + `Edit Fields`.

5. **Researcher sin acceso a internet** — Research-v1 inicialmente no podía obtener evidencia actual sin herramienta de búsqueda externa.

6. **Limitaciones de prompt** — Formatos intermedios (`EXECUTIVE BRIEF` / `FULL REPORT`) no alineados con el contrato operativo final de Research-v1; `Agent-Invocation-Standard.md` no participa en runtime n8n.

7. **`missing OPENAI_API_KEY` en Manager** — El servicio respondía error aunque PowerShell mostrara la variable en otra sesión.

8. **Inconsistencia de proceso Uvicorn en Windows** — Puerto 8000 asociado a PID inexistente (`34708`) con proceso hijo huérfano (`31764`) bajo `uvicorn --reload`.

9. **Rechazo de edición directa de `database.sqlite`** — Intento de modificar workflows vía SQLite desde Cursor fue rechazado; cambios deben hacerse en UI oficial de n8n.

10. **Errores tardíos en Manager Main** — Ejecuciones `error` al final del día (IDs 109–113, ~22:39–23:09).

11. **Documentación aprobada no persistida en repo** — `docs/specialists/Research-v1.md` y `workflows/Research-v1.json` acordados pero aún no creados en el working tree al cierre de la sesión.

# Solutions Implemented

| Problema | Causa raíz | Solución | Estado final |
|---|---|---|---|
| Campos vacíos en Research-v1 | Mapeo estático/desconectado en Manager Main | Form Trigger + `Edit Fields` con expresiones desde formulario y `authoritative_context`; cadena lineal hacia `Call Research-v1` | Parcialmente resuelto — ejecuciones exitosas confirman flujo; `workflowInputs.value` del nodo Call aún vacío en inspección final |
| JSON sin contexto | Padre no cargaba MasterContext | `Read/Write Files from Disk` + `Extract from File` con `destinationKey: authoritative_context` | Resuelto — ejecución 104 leyó `MasterContext_v2.md` |
| Mapeo Manager → hijos | Estructura anidada vs campos planos | `Edit Fields` mapea `Mission`/`Query` del form; `Edit Fields1` extrae `approved_research` de salida GPT | Resuelto en ejecuciones 101–108 |
| Nodos Merge | Complejidad innecesaria en ramas | Eliminación de Merge; flujo secuencial | Resuelto en grafo final |
| Sin internet en research | Falta de herramienta de búsqueda | Web Search built-in en nodo OpenAI de Research-v1 (medium context) | Resuelto |
| Prompt desalineado | Cambios en documentación no reflejados en nodo GPT | Prompt actualizado directamente en nodo `Message a model` de Research-v1 y Marketing-Strategist-v1 | Resuelto |
| `missing OPENAI_API_KEY` | Variable no heredada por proceso uvicorn hijo / terminal distinta | Definir `$env:OPENAI_API_KEY` **antes** de lanzar uvicorn en la misma terminal; reinicio limpio del proceso | Diagnóstico cerrado; requiere disciplina operativa |

| Edición SQLite | Ruta no soportada/aprobada | Configuración manual en editor n8n + montaje docker-compose para rutas de archivo | Política validada |
| Errores Manager Main 109–113 | No diagnosticado en detalle en esta sesión | Pendiente de revisión en UI n8n | Abierto |

# Architectural Decisions

1. **Researcher (Research-v1) posee solo evidencia** — Produce hallazgos, ideas accionables y riesgos; no decisiones de negocio, no estrategia, no contenido final.

2. **Marketing Strategist consume únicamente investigación aprobada** — Input obligatorio `approved_research`; no ejecuta research propio.

3. **El Strategist nunca investiga de forma independiente** — Prompt explícito: “You do not do research yourself”; sin Web Search en su nodo.

4. **Web Search pertenece solo a Research-v1** — Habilitado en GPT-5.5 de Research-v1; deshabilitado en Marketing-Strategist-v1.

5. **Separación de responsabilidades entre especialistas** — Manager orquesta; Research produce evidencia; Strategist convierte evidencia en plan; Office Manager archiva/documenta.

6. **Form Trigger reemplaza JSON manual fijo** — Entrada operativa vía formulario `Mission` + `Query`.

7. **`authoritative_context` inyectado, no duplicado** — `MasterContext_v2.md` permanece SSoT en `projects/oskar-corbenn/docs/`; se lee en runtime y se pasa como string al prompt.

8. **Documentación separada de workflows ejecutables** — `docs/specialists/*.md` para contrato/operación del especialista; `workflows/*.json` para export n8n.

9. **No editar `database.sqlite` para workflows** — Cambios solo por UI oficial de n8n o export/import soportado.

10. **Manager como orquestador LLM, no ejecutor de especialista** — `manager/manager.py` devuelve JSON de decisión; n8n ejecuta workflows hijos.

# Lessons Learned

- **La ejecución real expone fallas que el diseño no muestra.** Valores hardcodeados y nodos desconectados coexistieron con la impresión de “configuración correcta”; solo la inspección del workflow real y las ejecuciones revelaron el mapeo roto.

- **En Windows, `uvicorn --reload` distorsiona diagnóstico de procesos y variables de entorno.** PID stale en puerto 8000 y hijos sin `OPENAI_API_KEY` heredada son riesgos operativos reales.

- **El prompt del nodo n8n es la implementación.** Modificar `Agent-Invocation-Standard.md` u otros contratos documentales no cambia comportamiento en runtime.

- **La carga de contexto autoritativo debe resolverse en el flujo padre cuando Research-v1 es minimalista.** Mover lectura de `MasterContext_v2.md` a Manager Main simplifica Research-v1 y centraliza el ensamblado de inputs.

- **Eliminar Merge simplifica flujos lineales de especialistas.** La cadena Form → Context → Research → Strategy es más depurable que ramas fusionadas.

- **Validar la cadena completa requiere timestamps correlacionados.** Ejecuciones 107+108 en el mismo segundo confirman handoff Research → Marketing Strategist.

- **Commitear `database.sqlite` captura estado pero genera deuda de backup y tamaño de repo.** Útil como snapshot; no sustituye exports JSON versionados en `workflows/`.

# Technical Debt

### n8n API Key / credenciales OpenAI se pierden tras reinicio
**Priority:** High  
**Reason:** Sin credenciales persistidas, los nodos GPT fallan silenciosamente o en ejecución; bloquea toda la cadena operativa.

### `Call 'Research-v1'` con `workflowInputs.value` vacío
**Priority:** High  
**Reason:** Aunque las ejecuciones recientes fueron exitosas, el nodo muestra mapeo `{}` en inspección; frágil ante cambios de versión n8n o reconfiguración.

### Persistir exports JSON en `workflows/` y docs en `docs/specialists/`
**Priority:** High  
**Reason:** El estado vive solo en sqlite local; sin exports versionados, no hay recuperación limpia ni revisión en Git de cambios de workflow.

### Arranque manual de Manager con variable de entorno
**Priority:** High  
**Reason:** `OPENAI_API_KEY` debe exportarse en la misma sesión que uvicorn; proceso propenso a error humano.

### `uvicorn --reload` en Windows
**Priority:** Medium  
**Reason:** Genera procesos huérfanos y PIDs stale; dificulta diagnóstico de puerto 8000 y herencia de entorno.

### Script automatizado de startup/shutdown del stack local
**Priority:** Medium  
**Reason:** Hoy requiere pasos manuales dispersos (Docker n8n, Manager, variables, reinicios); aumenta tiempo de recuperación tras reboot.

### Documentación de arranque operativo
**Priority:** Medium  
**Reason:** No existe guía única que documente orden de inicio, variables requeridas y verificación de salud (Manager :8000, n8n :5678).

### Estrategia de backup de workflows
**Priority:** Medium  
**Reason:** Commit de `database.sqlite` mezcla datos runtime con código; se necesita política clara: export JSON periódico + sqlite fuera de Git o en `.gitignore`.

### Manager Main inactivo y errores recientes (exec 109–113)
**Priority:** Medium  
**Reason:** Flujo principal no está activo (`active: 0`) y registró errores al final del día; riesgo de regresión no investigada.

### Research-v1: recomendaciones más específicas por proyecto
**Priority:** Low  
**Reason:** Salidas genéricas limitan valor para Oskar Corbenn; requiere refinamiento de prompt y contexto de proyecto.

### Marketing Strategist: KPIs y métricas de plan
**Priority:** Low  
**Reason:** El plan de 7 días carece de criterios medibles explícitos; dificulta evaluación posterior en Content Engine.

### Añadir `uv` permanentemente al PATH de Windows
**Priority:** Low  
**Reason:** Mencionado como fricción operativa tras reinicio; no verificado en repo, pero afecta velocidad de arranque si se adopta como runner estándar.
